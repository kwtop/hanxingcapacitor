# HAN XING project instructions

This file supplements the active canonical global AGENTS.md with project publication rules.

- Keep completed changes local by default. Publish to Cloudflare only when the user explicitly requests the consolidated upload.
- Canonical public origin: https://www.hanxingcapacitor.com. Use `npm run deploy:public` for Cloudflare Pages production on the existing `hanxing-capacitor-preview` project, branch `main`. Both custom domains are attached to that project; do not create another site or database.
- `npm run build:public` prepares the public artifact without uploading. `npm run build:cloudflare` remains the explicitly configured low-level exporter. Public HTML must allow indexing, and robots/sitemaps/canonical/structured data must agree on the public origin.
- Public pages are open to visitors and crawlers. Preserve authenticated administration, protected inquiry/CSV APIs, CSRF and form validation. “Public access” concerns the public website, not disclosure of private inquiry records or admin credentials.
- Production administration uses Cloudflare Access email OTP with six-hour sessions and the approved account allowlist. The dedicated HAN XING Admin application covers `/admin`, `/admin/*` and `/api/admin/*` on www and apex only. Keep its Audience and team domain synchronized with Access. Supply the approved email allowlist in local deployment configuration. Local isolated QA retains password authentication; Pages origins must reject unsigned admin API requests with 401. Production edge challenges are validated against the exact Access application rather than treated as public API access.
- The canonical-www Single Redirect must exclude `/cdn-cgi` and `/cdn-cgi/*` as well as existing admin/API exclusions. Access authorization and multi-domain cookie callbacks must complete on their original hostname; canonicalizing them causes a login redirect loop. Verify the missing-state Access callback returns 400 without a canonical redirect and `/cdn-cgi/trace` returns 200 on both domains.
- Retain noindex on Pages preview domains and private/utility routes. A successful deployment is not proof of Google indexing.
- For this release run the existing check/build and isolated Pages smoke checks, then verify production routes, robots/sitemaps, key content, public bot responses, health and unauthenticated admin API rejection. Preserve original source files and image provenance records.
- Public identity is recorded in src/data/company.ts: HAN XING is the brand, Hangzhou Zebang is the head company in Hangzhou, and the Hebei address is the manufacturing facility. Reuse these distinct roles in copy and structured data.
- Public photograph displays and zooms use WebP delivery copies. Preserve native source files and provenance; run npm run prepare:images when changing source imagery. The red CBB61 wire-lead sample remains unretouched in both Guides, with a pixel-identical lossless full-resolution WebP copy. The six other guide sample photographs retain their selected retouched presentation. Do not restore the removed “View original photograph” links.
- Selected public layouts load the ordered styles in layout-selected.css; legacy/non-indexable layouts retain layout-legacy.css. Preserve screenshot geometry and interaction checks when changing style delivery. Editorial revision dates belong in src/data/contentRevisions.json and must not be refreshed by build or deployment.
- Spanish `/es/` is a real, indexable counterpart of every public English page, not a blanket migration redirect. Reuse English layouts through the prerendered locale middleware. Maintain source-aligned translations in src/i18n, preserve model/label values and provenance, and run scripts/compile-spanish.mjs and scripts/check-spanish.mjs before publication. Keep reciprocal en/es/x-default alternates and self-canonicals. Translation revision dates are manual in src/i18n/es-metadata.json. Admin remains outside public localization.
